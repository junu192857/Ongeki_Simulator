# 온게키 시뮬레이터 채보 형식 명세

> 버전: **v0.3 (설계 초안)** · 최종 갱신: 2026-10-19  
> 목적: OGKR의 파일 구조를 그대로 복제하는 대신, 온게키 핵심 게임플레이를 표현하는 독립 형식을 정의한다.  
> 이 문서의 '확정'은 논의된 원칙을 뜻하며, 예시 JSON의 필드명과 상세 스키마는 일부 미확정이다.

## 1. 개발 범위

**초기 구현:** METADATA, HEADER, PLATFORM, LANE, TAP/HOLD/WALL NOTE, FLICK, BELL.  
**후속 구현:** BULLET와 LASER (레이저도 탄막의 일부), 적 이동, 연출, 장식 전용 레인.

## 2. 시간·공간 좌표계 (확정)

- 시간을 `(unit, tick)` / JSON `[unit, tick]`으로 표현한다.
- **4분음표 네 개의 길이 = 1920틱**이므로 4분음표 1개는 480틱이다.
- `unit`은 마디 번호가 아니라 **고정 1920틱 단위**이고 `tick`의 정규화 범위는 0–1919이다.
- `absoluteTick = unit * 1920 + tick`; 실제 초 단위 시각은 BPM 변경 이력을 이용해 산출한다.
- 박자표 변경은 `unit` 길이를 변경하지 않는다. 예: 4/4 한 마디=1920, 6/4=2880, 6/8=1440틱.
- 캐릭터·레인·플랫폼·노트의 수평 위치는 실수 좌표로 표현한다. 수평 좌표의 원점 및 기준 폭은 미정이다.

## 3. 파일별 책임 (확정)

- **METADATA:** 곡 공통 정보. 제목, 아티스트, 음원 경로, 음원 길이, 난이도와 채보 파일 연결.
- **HEADER:** 채보별 BPM, 박자표, 레인·노트 스크롤 속도, 롱노트 중간 틱 판정 설정.
- **SETTINGS:** 사용자의 오디오 오프셋, 입력 보정 등. 채보 파일과 분리.
- 노트 총수 및 벨 총수는 레코드를 읽어서 계산한다.
- 음원 길이는 METADATA에 둔다.

### METADATA 후보 필드 (세부 스키마 미확정)

| 필드 | 타입 | 의미 |
|---|---|---|
| `title` | string | 곡 제목 |
| `artist` | string | 아티스트 |
| `audioFile` | string | 음원 상대 경로 |
| `audioLength` | number | 음원 길이, 초 단위 |
| `difficulties` | array | 난이도 이름·레벨·채보 파일 경로 |

Vexatonic Dash 2의 `METADATA.txt`에서 사용하던 NAME, ARTIST, MUSIC, LEVEL, LENGTH의 역할을 참고한다.

## 4. HEADER (구성 확정)

| 필드 | 의미 |
|---|---|
| `version` | 형식 버전 |
| `bpmChanges` | 시간별 BPM(4분음표 기준) |
| `meterChanges` | 시간별 박자표 분자/분모 |
| `scrollSpeedChanges` | 시간별 노트 및 레인 스크롤 속도 |
| `holdTickChanges` | 시간별 롱노트 중간 판정 간격 |

- 시간 분해능 1920은 파일 형식의 **고정 규칙**이므로 매 HEADER에 쓰지 않아도 된다.
- BPM, 스크롤 속도, 롱노트 틱 간격은 **서로 독립적으로 변경되는 설정**이다.
- **스크롤 속도는 노트와 레인의 표시 속도에만 적용**한다. 벨이나 탄막에 자동으로 적용하지 않는다.
- 스크롤 속도의 단위(배율/거리 단위)와 롱노트 틱 간격의 구체적인 단위(음악 틱/초)는 아직 확정되지 않았다.

예시(간격의 `intervalTicks` 필드는 잠정안):

```json
{
  "HEADER": {
    "version": "0.3",
    "bpmChanges": [{"time": [0, 0], "bpm": 180}],
    "meterChanges": [{"time": [0, 0], "numerator": 4, "denominator": 4}],
    "scrollSpeedChanges": [{"time": [0, 0], "speed": 1.0}],
    "holdTickChanges": [{"time": [0, 0], "intervalTicks": 240}]
  }
}
```

## 5. PLATFORM (핵심 규칙 확정)

플랫폼의 경계가 변하는 각 시점에 **`(시간, leftX, rightX)`** 키프레임을 저장한다. 인접 키프레임 사이의 좌우 경계는 각각 독립적으로 **3차 베지어(Cubic Bézier)** 보간한다.

- 경계마다 제어점 두 개를 갖는 구간 모델을 사용한다.
- **구체적인 데이터 표현 제안:** 두 내부 제어점의 시간 좌표는 구간의 1/3, 2/3에 고정하고 X좌표만 저장한다. 시작 키프레임의 `leftControlOut/rightControlOut` 및 다음 키프레임의 `leftControlIn/rightControlIn` 필드로 표현한다.
- `u = (currentTick - startTick)/(endTick - startTick)` (0–1)에 대해 위치는 아래처럼 보간한다.

```text
B(u) = (1-u)^3·P0 + 3(1-u)^2·u·P1 + 3(1-u)·u²·P2 + u³·P3
```

- 제어점이 시작점과 끝점 사이의 1/3, 2/3 위치에 일직선으로 놓이면 직선 보간도 표현 가능하다.
- **플랫폼 경계는 캐릭터의 물리적인 이동 가능 범위를 벗어날 수 있다.** 데이터 로딩·보간·렌더링에서 그 범위로 강제 제한하지 않는다.
- **캐릭터 위치 보정이 적용되는 시간 구간은 경계 키프레임과 별도로 저장**한다. 보정 구간 밖에서는 플랫폼 경계만을 이유로 캐릭터 좌표를 강제 보정하지 않는다.

예시(필드명 잠정):

```json
{
  "PLATFORM": {
    "points": [
      {
        "time": [0, 0], "leftX": -5.0, "rightX": 5.0,
        "leftControlOut": -4.0, "rightControlOut": 4.0
      },
      {
        "time": [1, 0], "leftX": -3.0, "rightX": 3.0,
        "leftControlIn": -2.0, "rightControlIn": 2.0
      }
    ],
    "correctionIntervals": [
      {"startTime": [0, 0], "endTime": [1, 0]}
    ]
  }
}
```

**미정:** 보정 방식과 경계 포함 여부, 제어점 필드 최종 명칭, 경계 불연속·교차·구간 밖 처리, 단일 키프레임 처리.

## 6. LANE (상세 정의 예정)

- 레인은 `id`, 색상/종류, 시간별 X좌표의 연속 경로로 표현한다.
- 같은 색 레인이 동시에 여럿일 수 있으므로 색상과 별개의 고유 ID가 필요하다.
- 곡선 표현은 플랫폼과 동일한 Cubic Bézier 계산 유틸리티를 재사용하는 방향이다.
- 플랫폼 좌우 경계를 가상의 벽 레인으로 취급한다.
- 장식 전용 레인은 초기 버전에서 제외한다.
- **미정:** 레인 생성/종료, ID 스코프, 벽 레인 참조, 제어점 필드.

## 7. NOTES 및 FLICK (상세 정의 예정)

- 탭 노트: 종류(빨강/초록/파랑/벽), 판정 시간, 보정 여부.
- 레인 종속 노트는 레인 ID를, 레인 밖 노트는 자유 X좌표를 저장한다.
- 롱노트는 종료 시간도 필요하다. 레인 종속 롱노트는 레인의 경로를 따르고, 자유 롱노트는 관절과 끝점의 시간·X좌표를 가진다.
- 플릭 노트는 판정 시간, 좌측 끝, 우측 끝, 방향을 가진다.
- **미정:** 실제 판정 및 보정 규칙, 롱노트 틱 생성, 플릭 범위의 의미.

## 8. BELL (상세 정의 예정)

- 후보 데이터: 시작·끝 시각, 시작·끝 X좌표, 속도.
- 벨 이동 시스템은 우선 HEADER 스크롤 속도와 별도로 정의한다.
- 이동 속도와 시간·위치 값이 중복으로 제약될 수 있으므로 기준값과 파생값의 관계를 추후 결정한다.
- 원본 OGKR의 팔레트·이동 규칙과 실제 게임 동작을 확인해 보완한다.

## 9. BULLET / LASER (초기 범위에서 제외)

탄막은 가장 복잡한 시스템이므로 초기 구현에서 제외한다. **레이저 역시 탄막 시스템의 일부**로 보고 같은 후속 단계에 함께 추가한다.
